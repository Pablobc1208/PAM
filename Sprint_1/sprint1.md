# Sprint 1


## 1. Necesidad detectada 
El documento identifica el problema central que PAM quiere resolver: **la espera del cliente para pedir y pagar en restaurantes**.

### ¿Quién sufre el problema?

| Actor | Impacto |
|---|---|
| **Cliente** | El [84 %](https://www.vinetur.com/20260714104206/el-62-de-los-espanoles-admite-un-simpa-o-la-tentacion-de-hacerlo-por-las-esperas.html) se frustra al tener que "perseguir" al camarero; el [~60 %](https://www.vinetur.com/20260714104206/el-62-de-los-espanoles-admite-un-simpa-o-la-tentacion-de-hacerlo-por-las-esperas.html) ha dejado de pedir postre o segunda bebida; el [54 %](https://www.vinetur.com/20260714104206/el-62-de-los-espanoles-admite-un-simpa-o-la-tentacion-de-hacerlo-por-las-esperas.html) elige restaurante por la velocidad del servicio. |
| **Camarero** | Trabaja con plantillas cortas (faltan entre [50.000 y 100.000 trabajadores](https://www.cio.com/article/2068277/el-sector-hostelero-se-cubre-las-espaldas-con-soluciones-tecnologicas.html) en el sector). Los picos de demanda generan estrés y tareas repetitivas. |
| **Dueño** | Pierde ventas por consumos que no llegan a pedirse. El [70 %](https://www.vinetur.com/20260714104206/el-62-de-los-espanoles-admite-un-simpa-o-la-tentacion-de-hacerlo-por-las-esperas.html) de los clientes penaliza la reputación si la cuenta tarda 5-10 min; el [62 %](https://www.vinetur.com/20260714104206/el-62-de-los-espanoles-admite-un-simpa-o-la-tentacion-de-hacerlo-por-las-esperas.html) admite haberse ido sin pagar o haberlo pensado. Algunos negocios tienen que [cerrar días por falta de personal](https://www.vozpopuli.com/espana/faltan-40-000-camareros-preguntan-cuantos-dias-tengo-que-trabajar.html). |

### Contexto y urgencia

- La hostelería concentra el [**13,37 %**](https://www.eldebate.com/espana/galicia/20260726/empresa-gallega-encuentra-solucion-cubrir-vacantes-hosteleria-forma-rapida_443319_amp.html) de las vacantes de difícil cobertura en España (SEPE).
- El [**51 %**](https://www.cio.com/article/2068277/el-sector-hostelero-se-cubre-las-espaldas-con-soluciones-tecnologicas.html) de restauradores considera la digitalización clave, pero solo el [**26 %**](https://www.alimarket.es/restauracion/noticia_amp/365816/square-analiza-la-digitalizacion-en-el-sector-de-restauracion) ofrece pago por QR.
- La escasez de personal es estructural y se agrava cada verano.

**Mensaje clave:** el cliente quiere al camarero presente, pero no quiere esperar. *Pide y Pam* libera al camarero de pedir y cobrar para que dedique su tiempo a atender.

## 5. Alternativas de solución

Se evaluaron tres alternativas técnicas para resolver el problema:

### Alternativas analizadas

| Alternativa | Ventajas | Desventajas |
|---|---|---|
| **A. Web por QR** | Sin descargas ni registro, barata, actualizaciones al instante | Depende del móvil y conexión del cliente |
| **B. App móvil nativa** | Notificaciones push, historial, fidelización | Barrera de descarga, doble desarrollo, cuotas de tiendas |
| **C. Tablet/kiosco en mesa** | No necesita el móvil del cliente | 150-300 €/mesa, averías, robos, mala escalabilidad |

### Comparativa ponderada (1-5)

| Criterio | Peso | Web QR | App | Tablet |
|---|---|---|---|---|
| Coste | 25 % | 5 | 4 | 1 |
| Fricción del cliente | 25 % | 5 | 2 | 5 |
| Tiempo de desarrollo | 20 % | 4 | 2 | 3 |
| Mantenimiento | 15 % | 5 | 2 | 1 |
| Escalabilidad | 15 % | 5 | 4 | 1 |
| **Total** | | **4,8** | **2,8** | **2,4** |

**Elección: Web por QR** — Se pide en segundos sin descargar nada, no obliga al restaurante a comprar hardware y se puede construir en el plazo del proyecto.

## 6. Viabilidad técnica

### Stack tecnológico elegido

| Parte | Decisión | Motivo |
|---|---|---|
| Frontend | **React** | Interfaces rápidas y adaptadas a móvil, componentes reutilizables |
| Backend / API | **Laravel (PHP)** | API REST, autenticación por roles |
| Tiempo real | **Laravel** | Pedido aparece en cocina al momento |
| Base de datos | MySQL o PostgreSQL (por definir) | Relacional, compatible con Laravel |
| Hosting | Railway/Render o VPS + Vercel/Netlify (por definir) | Planes gratuitos o baratos para la demo |
| Pasarela de pago | **Stripe (modo pruebas)** | Tarjetas de prueba y SDK para PHP y React |

### Infraestructura

- Desarrollo con portátiles, VS Code, PHP + Composer, Node.js, Git y GitHub. **Coste: 0 €**.
- Servidor y BD en plan gratuito o de estudiante. **Coste: 0 € o pocos euros/mes**.
- Pruebas con móviles propios y portátil/tablet como pantalla de cocina.
- Demo con QR impresos en papel.

### Competencias del equipo

| Necesidad | Estado |
|---|---|
| JavaScript y React | Por confirmar |
| PHP y Laravel | Por confirmar |
| Bases de datos SQL | Revisión |
| Integración de pagos (Stripe) | Hay que aprenderlo |

### Limitaciones técnicas

- Pagos solo en modo pruebas (cobrar de verdad requiere empresa y contrato con pasarela).
- Depende de la conexión del cliente.
- Sin integración con TPV reales.
- Seguridad del QR: el pedido solo pasa a cocina después de pagar.
- Equipo de 3 personas → alcance limitado a un MVP.

**Conclusión: el proyecto es viable.** React y Laravel cubren todo lo necesario, el hosting tiene opciones gratuitas, y lo nuevo (tiempo real y Stripe) está bien documentado.

## Resumen ejecutivo

**Pide y Pam** es una web por QR que permite a los clientes de restaurantes pedir y pagar desde su móvil sin descargar nada. El proyecto nace de un problema real: la espera frustra al 84 % de los clientes, genera pérdidas de ventas a los dueños, y la falta de personal en hostelería (50.000–100.000 trabajadores) es estructural.

Frente a la competencia (Sinqro, Cuatroochenta, McDonald's, Revo XEF), PAM se diferencia por integrar pedido, TPV y cocina en una sola solución sencilla. La alternativa web por QR fue elegida por su bajo coste, nula fricción para el cliente y rápida escalabilidad (puntuación 4,8/5 ponderada).

Técnicamente, el proyecto se construirá con **React** (frontend) y **Laravel** (backend), con **Stripe en modo pruebas** para pagos. El equipo de 3 personas (Pablo, Adrián y Manuel) entregará un MVP funcional con carta, carrito, pago, ticket y paneles de cocina, camarero y administración.
